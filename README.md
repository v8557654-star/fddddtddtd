# BACKROOMS // BODYCAM

Хоррор от первого лица на двух кастомных GLB‑картах (**Уровень 0 → Уровень 1**), снятый
«на бодикам». Godot 4.4+ (проверено на 4.7). Карты и модель монстра — из
`github.com/v8557654-star/models`; звуки, текстуры предметов и шейдеры сгенерированы кодом.

## Как запустить

1. Установи **Godot 4.4+** (стандартная сборка, не .NET).
2. Открой `project.godot` через *Project → Import* (или просто перетащи файл в Godot).
3. Дождись импорта текстур/звуков и жми **F5**.

Игра работает и в headless‑режиме (см. «Тесты» ниже).

| Клавиша | Действие |
|---|---|
| `W A S D` | движение |
| `Мышь` | обзор |
| `SHIFT` | бег (шумно! тратит выносливость) |
| `CTRL` / `C` | присед (тихо, ниже профиль) |
| `ALT` | очень тихий шаг |
| `F` | фонарь (батарея) |
| `V` | прибор ночного видения (батарея камеры) |
| `Q` / `R` | наклон корпуса |
| `E` | взаимодействие / подобрать |
| `ESC` | пауза |

### Мобильное управление (режим «МОБИЛЬНОЕ» в настройках)
* Левая половина экрана — плавающий джойстик движения.
* Правая половина — обзор свайпом (чувствительность отдельная в настройках).
* Кнопки: `ВЗАИМ.`, `БЕГ` (тумблер), `ПРИСЕД` (тумблер), `ФОНАРЬ`, `ПНВ`,
  `НАКЛОН Л/Р` (удерживать), `II` — пауза.
* На реальном телефоне режим включается сам (`OS.has_feature("mobile")`).

## Цель забега

1. **Уровень 0** («Вестибюль», `original_backrooms.glb`) — найди **дверь**. Она ведёт вниз.
2. **Уровень 1** («Бесконечный офис», `level1_big.glb`, ~180×180 м) — найди **аварийный выход**.

По пути собирай **миндальную воду** (рассудок + выносливость) и **батареи** (фонарь + камера) —
они складываются в **рюкзак (TAB)**, а используются когда решишь сам: клик по карточке или клавиши 1 / 2.
Пока рюкзак открыт, игра на паузе.
Предохранителей и молока больше нет — только дверь, свет и оно.

## Что внутри

### Карты (`scripts/world/level_defs.gd` + `custom_map.gd`)

Таблица уровней в `LevelDefs.LEVELS` (путь к GLB, масштаб, шаг ламп, доля рабочих ламп,
число предметов, интенсивность галлюцинаций, текст цели). `CustomMap.build(seed, level_id)`:
- загружает GLB и строит по его треугольникам сетку проходимости (ячейка 0.75 м), trimesh‑коллизию
  с `backface_collision` (у комьюнити‑карт пол бывает вывернут);
- оставляет крупнейшую связную область, строит `AStarGrid2D`; клетки у стен дороже, чтобы монстр
  ходил по центру коридоров;
- расставляет лампы только под «типичным» потолком (без парящих панелей над дырами в меше);
- ставит **дверь** (рама + полотно + табличка + свет) в самой дальней от спавна клетке, вплотную к стене;
- раскладывает воду/батарейки. Раскладка зависит от сида, геометрия — нет.

Переход между уровнями: `main.gd → on_door_used()` — затемнение, полная пересборка мира,
`_spawn_level(next)`. На последнем уровне дверь = победа.

### Галлюцинации (`scripts/monster/phantom.gd`)

Отдельный «фантом» с той же моделью, работает на **обоих** уровнях, не убивает, но бьёт по рассудку:
- **PEEK** — выглядывает из‑за угла впереди (наклоняется из стены). Посмотришь ≥0.45 с — либо
  растворяется в помехах, либо **CHARGE**: бежит прямо в камеру и исчезает в 1.5 м со скримером.
- **BEHIND** — материализуется в 2–3 м за спиной с дыханием и рыком; обернёшься — скример‑вспышка и
  пропадает (или бросается).
- **GLIMPSE** — стоит неподвижно в 15–25 м на периферии; смотри дольше секунды — исчезнет.
- **Аудио** — рык прямо у уха, бегущие шаги сзади, которые обрываются.
Частота × `intensity` уровня (Уровень 1 = 1.45). Выключается галочкой «Галлюцинации».

### Монстр (`scripts/monster/`)
* **Эскалация «menace» 0→3.** Первые встречи — только запугивание, убивать оно начинает
  не сразу:
  - **STARE** — заметив тебя впервые, оно не бежит: останавливается, поворачивается и смотрит
    (глаза пульсируют красным, низкий рык). Убежишь — отпустит; будешь стоять — пойдёт.
  - **APPROACH** — медленно идёт на тебя с вытянутыми руками. На menace 0 доходит до 3 м и
    **рассыпается в помехи**; на menace 1 срывается в бег.
  - **Ложная атака** — на menace 1 погоня заканчивается полноценным скримером в объектив,
    но ты остаёшься жив (−30 рассудка, «СИГНАЛ ПОТЕРЯН»). После этого menace = 2 — **летально**.
  - **AMBUSH** — пока не смотришь, оно ставит себя в 12–22 м впереди по ходу движения и ждёт под
    лампами; поднял глаза — начинается STARE; прошёл мимо вплотную — APPROACH.
  - **STALK** — прежняя механика «за спиной».
  Каждый испуг повышает menace, плюс +1 каждые 2,5 минуты. На «Кошмаре» летально уже с menace 1.
  Шум вблизи на нелетальных стадиях вызывает расследование, а не мгновенную погоню.
* Модель `models/monster.glb` («Minecraft Monster», ~2.85 м). `monster_model.gd` при загрузке
  перевешивает ноги/руки/торс модели под свои пивоты и гонит процедурную походку, твичи, наклон
  корпуса, слежение головой за игроком и красную подсветку глаз по `awareness`.
* ИИ‑машина состояний: `WANDER / STALK / INVESTIGATE / CHASE / SEARCH / STUN`.
  * **Слух**: радиус зависит от бега/ходьбы/приседа игрока и сложности.
  * **Зрение**: конус + линия видимости + модификаторы света
    (фонарь игрока = видеть дальше; присед = ближе).
  * **Погоня**: ведёт упреждение по скорости игрока, частый пересчёт пути,
    не бросает преследование в упор без линии видимости, обходит препятствия
    умным сайдстепом (выбирает открытую сторону).
  * **Сталкер**: периодически материализуется в 6–9 м за спиной и идёт вплотную
    следом; обернёшься и удержишь взгляд ~0.5 с — замирает и исчезает
    (помехи, шёпот); дотянется до спины незамеченным — скример‑вспышка и −25 рассудка.
* Грация: первые N минут (настройка, по умолчанию 3) монстр спит вне уровня;
  затем **ГРОХОТ** (дальний удар + стингер + помехи камеры) — и он просыпается
  в нескольких комнатах от игрока.
* Вокализации: рычание, скрежет, мокрое дыхание (3D‑позиционирование), шаги.

### Игрок (`scripts/player/`)
* FPS‑контроллер: ускорение/трение, спринт, присед, наклоны, head‑bob,
  процедурное «ручное» покачивание камеры, шаги разной громкости.
* Выносливость, **рассудок (sanity)**, страх (`fear`), батареи фонаря и камеры.
* Дыхание и сердцебиение при усталости/страхе, автоэкспозиция камеры.

### Бодикам (`shaders/bodycam.gdshader` + `scripts/ui/bodycam.gd`)
Полноэкранный пост‑процесс по `hint_screen_texture`:
* баррельное искажение объектива + виньетка;
* хроматическая аберрация по краю кадра;
* rolling‑shutter (построчный сдвиг) + микро‑шейк «с рук»;
* аналоговое зерно, строчная развёртка, грязь/царапины/отпечатки на линзе;
* квантование видеочасы до 24 Гц + случайные пропущенные кадры;
* tracking‑band / разрывы строк и статика при помехах;
* деградация картинки при низком рассудке, красная вспышка урона;
* режим **ПНВ** (фосфорно‑зелёный, свой шум и виньетка);
* OSD: `REC`, тайм‑код 24 fps, батареи, цели, субтитры, предупреждения.

### Атмосфера
* Объёмный/высотный туман, ACES, SSAO, glow, тусклый тёплый ambient.
* Процедурный звук: гул ламп 100 Гц, room‑tone, стоны конструкций, шёпот,
  дальние удары, гудение ПНВ, скример‑стингер (всё в `audio/`, генератор — `tools/generate_assets.py`).
* События страха: гаснущие рядом лампы, шёпот при низком рассудке, помехи камеры.
* Скример: при поимке slow‑mo, монстр прыгает в объектив (`lunge_at_camera`),
  полноэкранная вспышка процедурного лица (`textures/jumpscare.png`), тряска и
  рывок FOV, статика + скрежет; отключается галочкой «Скримеры».

### Прогрессия/режимы
* 3 сложности (туриста / стандарт / кошмар) — скорость, слух, зрение монстра, дрейн рассудка.
* Настройки (два столбца, значения видны, **применяются на лету**, «Сбросить»): чувствительность
  мыши/тача, FOV, 4 громкости, зерно/развёртка/виньетка, туман, head‑bob, субтитры, инверсия Y,
  FPS, сложность, схема ПК/мобильная, пауза до монстра, галлюцинации, скримеры, сид.
  Сохраняются в `user://settings.cfg`.
* Главное меню: VHS‑стиль, глитчащий заголовок, силуэт монстра под мигающей лампой (SubViewport).

## Радар выхода, декор, совместимость (v4)

- **Пеленгатор выхода** (HUD, правый верх): круглая шкала со свипом; точка = направление
  на дверь относительно взгляда, радиус = дистанция (лог-шкала), обновляется только когда
  луч проходит по цели и «плывёт» тем сильнее, чем дальше дверь. Подпись: `ВЫХОД N м`,
  на уровне 2 пока паук не ушёл — `ЗАБЛОКИРОВАН`. Нарисованные стрелки на полу убраны.
- **Декор**: опрокинутые стулья (Kenney Furniture Kit, CC0 — `models/props/`, см.
  `LICENSE_KENNEY_FURNITURE.txt`) и бумага на полу (`textures/paper.png`, атлас 2×2
  из `tools/generate_assets.py::build_paper`). Количество — ключи `chairs` / `papers`
  в `level_defs.gd`. Стулья сталкиваются только с игроком (слой 16), монстры проходят;
  клетки под стульями дороже для A*, так что пути существ их обходят.
- **Windows без Vulkan/SM6**: `fallback_to_d3d12=false`, `fallback_to_opengl3=true` —
  игра сразу уходит в Compatibility вместо падения D3D12.
- **Звук в APK**: `audio_bank.gd` грузит `res://audio/*.wav` через remap-заглушки
  (`.import`/`.remap`) + запасной MANIFEST; раньше экспортированная сборка была немой.

## Скример-укус (v5)

- Первый монстр при поимке **кусает**: у модели голова разделена на шею (`neck`) и
  челюсть (`jaw`, нижняя часть морды bone6) — челюсть распахивается и захлопывается
  ~2.4 раза/с (`MonsterModel.bite()`), голова дёргается, руки обхватывают камеру.
  Камера прижата к пасти (0.2–0.4 м), FOV сужается, сильная тряска; на каждый
  щелчок челюсти — красная вспышка, помеха и кадр «лица».
- Новый звук `audio/jumpscare_scream.wav` (`tools/generate_assets.py::aud_jumpscare`):
  суб-удар, рычание через форманты, металлический визг с вибрато и ринг-модуляцией,
  шумовой выброс, щелчки укусов, бит-краш + хард-клип. Играет на отдельной шине
  **Jumpscare** (+6 дБ, лимитер, не зависит от ползунка громкости монстра) в две
  копии (обычная + октавой ниже) плюс стингер; ложная атака — та же шина, тише.

## Анимация паука и оптимизация (v6)

**Паук (уровень 2).** В `spider.glb` нет скелета — только 135 жёстких кусков.
`spider.gd::_rig_legs()` находит 8 контейнеров ног (по суффиксам `_126/_134`,
`_138/_140`, `_136/_142`, `_146/_144`) и подвешивает бедро → колено на новые
пивоты `Hip_*`/`Knee_*` в точках суставов (координаты сняты с геометрии
через numpy). `_animate()` крутит их «рысью» (диагональные пары в противофазе,
фаза = `walk_phase`, накапливается от скорости): шаг вперёд-назад по Y,
подъём бедра и сгиб колена по Z, амплитуда растёт от скорости. Стоя — лёгкое
переминание, в состоянии FREEZE — мелкая дрожь; брюшко (`_128`) покачивается,
корпус подпрыгивает в такт шагам. `BR_LEGTEST=<фаза>` замораживает позу для
скриншотов.

**Слияние мешей** (`scripts/world/mesh_merge.gd`, `MeshMerge.merge_subtree`).
Складывает сотни MeshInstance3D в один ArrayMesh на материал (опционально
чанками по 14 м, чтобы фрустум-куллинг продолжал работать). Геометрия,
материалы и UV копируются как есть — картинка не меняется.
Применяется к: карте GLB (`custom_map.gd::build`, коллизия строится уже по
слитым мешам), телу паука (~120 кусков → 1 меш из 3 поверхностей, ноги
остаются отдельными для анимации), бумаге на полу (`Clutter/Paper`).
Отключить для сравнения: `BR_NOMERGE=1`.

| уровень | было: инстансов / draw calls | стало |
|---|---|---|
| 0 | 275 / 180 | 206 / 178 |
| 1 | 1665 / 803 | 785 / 371 |
| 2 | 1209 / 1330 | 128 / 234 |

**Текстуры.** Все текстуры ≥512² из `models/*.import` переведены на
`compress/mode=2` (VRAM-компрессия S3TC/ETC2 с мипмапами): ~4× меньше видеопамяти
и трафика памяти, что особенно заметно на телефонах и слабых видеокартах.
Материалы паука дублируются один раз на исходный материал (а не на каждый меш).

## Уровень 3 — «Яма»: квест на выход (v7)

**Карта** — `models/level7.glb` («Rec Room — Backstage of Reality Level 7», Lol_o9, CC‑BY,
18.5 МБ): бетонный лабиринт 72×128 м с открытым верхом. Загрузчик `custom_map.gd`
получил новые ключи `level_defs.gd`: `cull_above_glb` (срезать всё выше среза — домик,
рельеф, декор сверху), `clip_glb` (bbox играбельной плиты; сетка A* привязана к нему),
`floor_y_glb`, `wall_clear` (зазор клетка↔стена; 0.37 м — диагонали не «протекают»
сквозь полуметровые стены), `ceiling_h` + `ceiling_hole_glb` (процедурная бетонная
крышка над лабиринтом с вырезом под лестничную шахту), `albedo_min` (экспорт содержит
почти чёрные albedo‑факторы 0.009 поверх нормальных текстур — поднимаем до 0.42),
`spawn_glb`/`key_glb`/`door_glb`+`door_yaw_deg`, `rubble_*`, `stairs_*`, `chase_from_glb`.
`_make_door()` вынесен из `_exit()` и переиспользуется для люка.

**Сценарий** — `scripts/world/level7_script.gd` (фазы `SEARCH_KEY → TO_DOOR → DIG → CLIMB → DONE`):

1. **Ключ.** Ржавый ключ (`pickup.gd::Type.KEY`, увеличенный, с тёплым свечением) лежит
   в дальнем северо‑западном кармане лабиринта (~155 м пути от спавна). Пеленгатор HUD
   ведёт на ключ (`director.radar_target()`). Ключ — третья карточка рюкзака (`[3]`,
   не расходуется по клику, применяется у двери). **В момент подъёма ключа просыпается
   монстр** (`_activate_monster`, обычная система menace — сначала пугает).
2. **Железная дверь** на востоке. Клетки за ней заперты в A* и в `data.solid`, пока не
   открыта; у двери — своя подсказка/реакция (`director_door_prompt()`,
   `director_door_interact()` в `main.gd`, `exit_area.gd`). С ключом: `unlock.wav`, створка
   поворачивается на петле (tween), ключ списывается.
3. **Завал.** За дверью тупик, в 0.9‑метровом проёме к нише — куча земли
   (`_build_rubble`: холм + 14 комьев, StaticBody + Area3D `rubble_area.gd`).
   **Держать E** ~22 с (`player.interact_held()`, на телефоне — удержание кнопки ВЗАИМ.,
   `touch_interact_held`): подсказка с процентами, куча оседает, каждый «черпок» —
   `dig_1..3.wav` + шум радиусом 26 м → монстр идёт на звук, менace ≥ 1. Тратится
   выносливость. В конце `collapse.wav`, клетки открываются.
4. **Лестница.** Процедурная стальная лестница (22 ступени, рампа‑коллайдер 42°, перила,
   стенки шахты, площадка над крышкой) ведёт вверх через вырез. Шаги по ней —
   `stairs_1..3.wav`. Через 2 с после расчистки — **финальная погоня**: монстр появляется
   у железной двери с menace 3 (смертелен), «ОНО ЗДЕСЬ. НАВЕРХ!».
5. **Люк** на площадке (`hatch_area.gd`) → победа («ЛЮК ОТКРЫТ · НАВЕРХУ — НЕБО»).

Уровень 2 больше не последний: красная дверь Закулисья ведёт на уровень 3
(`door_red`, `door_is_exit: false`).

**Звук** (`tools/generate_assets.py::build_level7`): `dig_1..3`, `key_jingle`, `unlock`,
`collapse`, `stairs_1..3`.

**Тест‑хуки:** `BR_LEVEL=3`, `BR_L7_AUTO=1` (бот проходит квест целиком: ключ → дверь →
копает → лестница → люк, ~135 с), `BR_L7_PHASE=door|dig|climb` (прыгнуть к фазе),
`BR_L7_KEY=1`, `BR_L7_NOCHASE=1`, `BR_WALLCLEAR=<м>`, `BR_MAPDBG=1` (дамп сетки).

**Размер репозитория.** Все GLB перепакованы: текстуры вынесены из бинарного буфера
в соседние `models/<имя>_N.png|jpg` (те же байты, что Godot и так извлекал при импорте,
`gltf/embedded_image_handling=1`), а в GLB остались ссылки `uri`. Итог: `models/`
95 → 59 МБ (текстуры в PNG плюс GLB без дублей), картинка и коллизии не изменились.

**APK (v7).** `apk/backrooms_bodycam.apk` — debug‑сборка, arm64‑v8a, minSdk 24,
versionCode 7. Собрано `godot --headless --export-debug "Android"` с Godot 4.7.2
(шаблоны 4.7.2.stable, JDK 17, Android SDK build‑tools 34). Подпись — debug‑ключ,
на телефоне нужно разрешить установку из неизвестных источников.

**Ужатие (v7.1).** Текстуры моделей без альфы — из PNG в JPEG (базовый цвет q90,
карты нормалей q92 без субдискретизации цвета; PNG остались только у монстра, там
альфа) — 37 → 14 МБ; ссылки в GLB обновлены. Звук — WAV → OGG Vorbis (12 → 1.1 МБ;
`audio_bank.gd` понимает оба формата, зацикливание через `AudioStreamOggVorbis.loop`,
`generate_assets.py` пишет OGG сразу). Проект целиком: 77 → 44 МБ (оставшиеся 23 МБ — геометрия четырёх GLB).

**Фикс v7.1 (телефон).** После подбора предмета с сенсорной кнопки подсказка
«[E] … — ВЗЯТЬ» оставалась на экране навсегда: `try_interact()` (путь кнопки)
не сбрасывал цель, а проверка `_interact_target != null` пропускала уже
освобождённый объект. Теперь оба пути идут через `_set_prompt()`, а на телефоне
подсказка показывает `[ВЗАИМ.]` вместо `[E]`.

## Оптимизация под телефон (v8)

Диагностика (`BR_STATS=1` печатает `STATS lights/chunk`, `BR_PERF=1` — FPS/draw calls
раз в 2 с): главный тормоз на мобильном рендерере Godot — не полигоны, а **свет на
объект**. Mobile‑рендерер считает каждый OmniLight, задевающий объект, для *всех* его
пикселей (и молча обрезает после 8). После слияния мешей огромные исходные меши (пол
на 187×187 м на уровне 1, плита‑лабиринт 72×129 м на уровне 3, потолочная крышка) целиком
попадали в один чанк по своему центру → объект размером с карту, который никогда не
отсекается фрустумом и освещён **197 лампами** (L1) / 46 (L3).

Что сделано:
- `mesh_merge.gd`: меши крупнее 1.5 чанка режутся **по треугольникам** по чанкам,
  а длинные треугольники дополнительно делятся по самому длинному ребру
  (`_append_split`/`_emit_tri`, нормали/тангенты/UV/цвета интерполируются —
  картинка та же). Худший чанк: L1 197→13 ламп, L3 46→12.
- `custom_map.gd::_ceiling_slab`: крышка Ямы нарезана плитками по размеру чанка
  (было: одна плоскость 77×67 м под 31 лампой).
- На телефоне чанк 10 м вместо 14 (`GameSettings.gfx_chunk()`), 3D‑масштаб LOW 0.7.
- `project.godot`: `window/stretch/mode.mobile="viewport"` — на телефоне вся сцена
  рендерится в 1280×720 и растягивается, а не в нативные 2400×1080.
- Все текстуры моделей — `compress/mode=2` + мипмапы (ETC2/ASTC на Android,
  `texture_format/etc2_astc=true` в пресете): 4–8× меньше трафика памяти GPU,
  без мипмапов на телефоне текстуры 1024² ещё и «шумели» вдали.
- `bodycam.gdshader`: `screen_tex` без `filter_linear_mipmap` — мобильный рендерер
  не строит мип‑цепочку экрана каждый кадр.
- Служебные хуки: `BR_FAKE_MOBILE=1` (эмулировать мобильные настройки на ПК),
  `BR_GFX=n` (пресет), `BR_PERF=1`, `BR_STATS=1`.

## Два тоннеля и «Беги или умри» (v9)

За люком на Уровне 3 больше нет неба. Там бетонный тамбур и **два одинаковых
тоннеля** под красными лампами. Какой из них какой — решает сид забега
(`run_seed`), подсказок нет.

* **Тоннель-ловушка.** На восьмом метре плита пола уходит из-под ног. Камера
  летит вниз по бетонной шахте (красный проём тоннеля сжимается над головой,
  мимо мелькают рёбра и мёртвые лампы), свист ветра, затемнение — и экран
  **«ПРОПАСТЬ»** (`kind="fall"`). Шахта отрисовывается на отдельном
  render-слое (2) высоко над картой: под настоящим полом тоннеля — лабиринт.
* **Тоннель-выход** → **Уровень 4 «БЕГИ ИЛИ УМРИ»** (`scripts/world/run_level.gd`
  + `run_script.gd`). Полностью процедурный: прямой тоннель 150 м, красные
  аварийные лампы, стальные рёбра, трубы, обломки, и **белый свет в конце**.
  Тоннель трясёт (тряска камеры через `Player.shake`, гул `quake.ogg`
  с толчками), с потолка падают куски бетона (`rock_hit_*.ogg`), лампы
  мигают в такт. **За тобой бегут оба** — существо и паук, с рёвом, оба
  смертельны, оба чуть медленнее твоего спринта (4.4 / 4.3 м/с против 5.4),
  с «резинкой»: чем дальше отстали, тем сильнее давят. Выносливость
  расходуется вдвое медленнее обычного, но на 150 м её всё равно не хватает —
  беги, переводи дух шагом, снова беги. Пешком — гарантированная смерть
  (проверено ботом: смерть на ~35 м). Добежал до света — экран
  **«ВЫ ДОБЕЖАЛИ»** (`kind="run"`).

Что изменилось в коде:

* `level_defs.gd` — Level 4 (`"procedural": "run"`, `"scripted": "run"`).
* `main.gd` — выбор класса уровня по `procedural`, `win_game(kind)`,
  `fall_ending(stage)` + `_tick_fall` (сценарное падение), `_end_kind`
  прокидывается в `menus.set_end_screen(..., kind)`; сброс fade/fall в
  `_clear_run`.
* `level7_script.gd` — фаза `TUNNELS`: люк теперь открывается (створка на
  петле, коллизия снимается), за ним тамбур + тоннели (`_build_tunnels`),
  ловушка (`_on_trap_entered`), шахта падения (`_build_fall_stage`),
  переход на Level 4 (`_on_run_exit` → `on_door_used`).
* `player.gd` — `shake` (аддитивная тряска камеры, 0 = выключена) и
  `stamina_drain_mul`.
* `spider.gd` — «резинка» скорости не превышает `speed_chase`.
* Новые ассеты: `textures/concrete(.png,_n.png)`, `audio/quake.ogg`
  (луп), `fall_wind.ogg`, `rock_hit_1..3.ogg` — все генерируются
  `tools/generate_assets.py` (`build_v9`).



Тест-хуки: `BR_L7_PHASE=tunnels` (сразу на площадку с открытым люком),
`BR_L7_PIT=left|right` (принудительно сторона ловушки), `BR_L7_GO=run|pit`
(бот `BR_L7_AUTO=1` идёт в нужный тоннель), `BR_RUN_AUTO=1`
(бот бежит Level 4 с передышками), `BR_RUN_AUTO_WALK=1` (идёт пешком),
`BR_RESTART_AT=сек` (нажать «повторить» из теста), `BR_POSE=x,z,yaw,pitch,y`.

## Кооператив по сети: LAN / точка доступа / интернет (v10)

До **четырёх операторов** в одном мире. Один создаёт комнату, остальные
подключаются по его IP. Существо одно на всех и живёт на хосте; погибший
не выходит из игры — он **смотрит глазами живого напарника** до конца
записи.

Как играть:

1. Главное меню → **«ВМЕСТЕ · LAN / ИНТЕРНЕТ»**, впиши позывной.
2. Хост: **«СОЗДАТЬ КОМНАТУ»** — на экране появится IP хоста в сети
   (`ТВОЙ IP В СЕТИ: 192.168.43.1 …`). Порт всегда **UDP 7777**.
3. Остальные вводят этот IP и жмут **«ПОДКЛЮЧИТЬСЯ»**. Можно `ip:порт`.
4. Когда все в списке (CAM 01…04) — хост жмёт **«НАЧАТЬ ЗАПИСЬ ВМЕСТЕ»**.
   Плёнка одна: уровень строится по общему сиду у всех одинаково.

Сети:

* **Точка доступа с телефона / один Wi-Fi** — ничего настраивать не надо,
  хост говорит свой IP (он показан в меню), остальные вводят его.
* **Интернет** — на роутере хоста пробросить **UDP 7777** на его ПК и дать
  друзьям внешний IP. Или любой VPN-«локалка» вроде Radmin/ZeroTier/Hamachi —
  тогда как по LAN.
* Android-сборка: в `export_presets.cfg` добавлено `permissions/internet=true`.

Правила кооператива:

* Все — операторы с камерами, никакого монстра среди игроков. Существо и
  паук ходят за **ближайшим** живым; во время погони цель не меняется, пока
  та не умрёт (или кто-то не влезет прямо под лапы).
* Смерть → камера напарника (`ЛКМ` / `E` — переключить, если живых больше
  одного). Умерли все — общий экран «ЗАПИСЬ ПРЕРВАНА».
* Дверь между уровнями открывает любой — спускаются **все сразу**. Победа
  и «БЕГИ ИЛИ УМРИ» (Level 4) тоже общие: добежал один — плёнка сохранена у
  всех.
* Ржавый ключ (Level 3) один на команду: кто поднял, тот и открывает; завал
  копают вместе — две лопаты вдвое быстрее. Люк открывает любой, в тоннели
  каждый входит сам: провалившийся в пропасть уходит в наблюдатели, добежавший
  до конца уводит всех на Level 4. Ящик на Level 2 вмещает одного; паук,
  потеряв спрятавшегося, переключается на того, кто снаружи.
* Вода и батареи — личные (кто взял, тому и в рюкзак), у всех предмет
  исчезает.
* Пауза в сети не останавливает мир — меню лишь забирает управление. Рюкзак
  тоже открывается «на ходу».
* Напарники видны как фигуры в тёмных куртках с нагрудной камерой и
  мигающим красным REC, позывной читается с 16 м. Их фонари светят
  по-настоящему. Список экипажа — слева вверху (● живой, ■ запись
  прервана).

Реализация (ENet, хост-авторитарно, без изменений в одиночной игре):

* `scripts/autoload/net.gd` (автолоад `Net`) — комната, лобби, RPC:
  `ev` (надёжные события), `p_state` (позы игроков, 20 Гц),
  `m_state` (существо/паук с хоста, 20 Гц).
* `main.gd` — `remotes{}` (аватары), `net_event()` / `net_player_state()` /
  `net_monster_state()`, `_retarget_ai()`, состояние `SPECTATE`,
  `_start_spectate/_tick_spectate`, общие `door_used/win/kill/pick`,
  `_slot_index/_spawn_slot` (стартуют плечом к плечу).
* `player.gd` — режим `remote` (аватар без ввода, интерполяция позы,
  `net_apply`, `remote_die`), `net_flags()`.
* `monster.gd`, `spider.gd` — режим `puppet` на гостях (`puppet_apply`):
  ИИ не считается, поза и звуки состояний воспроизводятся.
* Директора уровней (`backstage_script.gd`, `level7_script.gd`,
  `run_script.gd`) — `net_apply()` для фаз, копания, люка, ловушки; хост
  ведёт паука и переходы фаз.
* `custom_map.gd` — `pool.shuffle()` заменён на сидированный
  `_seeded_shuffle` (иначе предметы и стулья у пиров расходились).
* `hud.gd` — `set_crew()`, `set_spectating()`; `menus.gd` — экран `NET`.

Тест без второго ПК (два процесса): `BR_NET_HOST=1 [BR_NET_PEERS=n]` и
`BR_NET_JOIN=127.0.0.1` (+ обычные `BR_LEVEL`, `BR_SEED`, боты
`BR_L7_AUTO`, `BR_RUN_AUTO`, `BR_BS_AUTO`); `BR_SHOW_NET=1` — сразу экран
«Вместе». Проверено: Level 0 → 1 общий спуск, Level 2 (3 пира, паук ловит
двоих, третий прячется и уводит всех на Level 3), Level 3 (общее копание,
один падает в пропасть → наблюдатель, второй добегает → Level 4), Level 4
(один гибнет и смотрит, второй добегает → общий «ВЫ ДОБЕЖАЛИ»).

## Модель напарника (v11)

Аватар второго оператора в кооперативе — больше не коробки: используется
KayKit «Rogue Hooded» (Kay Lousberg, CC0, kaylousberg.com), урезанный до
нужного: `models/operator.glb` (0.45 МБ, 6 анимаций — Idle, Walking_A,
Running_A, Death_A, Interact). Урезка — `tools/strip_glb.py`:

    python3 tools/strip_glb.py Rogue_Hooded.glb models/operator.glb \
        --keep-anim Idle,Walking_A,Running_A,Death_A,Death_A_Pose,Interact \
        --drop-node Knife_Offhand,1H_Crossbow,2H_Crossbow,Knife,Throwable,Rogue_Cape

Материалы затемняются под общий полумрак, на груди — бодикам с красным REC,
над головой — позывной. Походка/бег подбираются по реальной скорости из
сетевых пакетов, смерть проигрывает Death_A. Если GLB отсутствует,
игра откатывается на старый силуэт из примитивов.
